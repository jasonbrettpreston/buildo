## Ground truth (source-verified; ✅ = confirmed, ⚠️ = corrected from my draft)
**G1 ✅ Chromium launches and runs fine.** Its own log shows a normal 2.2 s cold startup (dbus noise, favicon/quota/password-store/top-sites/UKM DB creation, UPower + screensaver probes). No fatal error.
**G2 ✅ nodriver's CDP connect budget is 2.25 s, hardcoded, unconfigurable.** `nodriver/core/browser.py:425-449`: `sleep(0.25)` then `for _ in range(5): … await self._http.get("version") … except: sleep(0.5)` → last probe at T+2.25 s, raise at ~T+2.75 s. Identical in 0.48.1 **and** the 0.50.3 wheel. On Linux a closed port refuses instantly, so the per-request `timeout=10` never applies — the real grace period is 2.25 s against G1's 2.2 s+ of cold-profile DB creation. **This is attempt 1's failure.**
**G3 ✅ CI has never run the version proven locally.** `requirements.txt` says `nodriver>=0.48` (unbounded); local = **0.48.1**, PyPI latest = **0.50.3**, so CI silently resolves to 0.50.3.
**G4 ⚠️ CORRECTED — my draft blamed my own tripwire; the evidence says otherwise.** I claimed 0.50.3 never populates `browser.connection`. The explorer showed that in 0.48.1 `.connection` is a plain attribute, never re-nulled, and `browser.get()` itself routes through `self.connection.send` (`browser.py:568`) — so the `'NoneType' object has no attribute 'send'` we saw most likely originated **inside `browser.get('about:blank')`**, not my check, and means `uc.start()` returned via an early-return path (`browser.py:359-366`). Either way the tripwire must stop reading library internals (F4), but I am no longer asserting it caused the attempt-2/3 failures. **Attempts 2–3 are explained by G5 instead.**
**G5 ✅ Orphaned Chrome guarantees the retries fail.** The raise happens *inside* `start()`, so `Browser.create` never returns and the caller never gets a handle to `.stop()`. The spawned Chromium is referenced only by `util.__registered__instances__`, drained solely at `atexit`. So attempt 1's browser stays alive holding the profile; attempts 2–3 either hand off their command line to it and exit, or collide on the profile ("database is locked", "Failed to write a new fake index" — both in our log). **Corollary: the clean startup log I read was probably the orphan's, not the failing attempt's.**
**G6 ✅ Version identity is nearly identical across the working/failing split** — local branded **Chrome 150.0.7871.125** vs CI unbranded **Chromium 150.0.7871.0**, same major+build. Kills the "nodriver vs Chromium 150" theory I held earlier.
**G7 ✅ `page.send(...)` is version-stable** (`Connection.send` + `class Tab(Connection)` in both versions); `browser.connection` is not.
**G8 ✅ nodriver never reads `DevToolsActivePort`** (zero hits package-wide). If Chrome cannot bind the requested port it picks another, writes it only to that file, **stays alive**, and nodriver is permanently blind.
**G9 ✅ Free-port selection is a TOCTOU race** (`util.py:139-143` binds port 0, reads it, closes, *then* spawns Chrome). Acute with parallel workers.
**G10 ✅ Chrome's stdout/stderr are `PIPE`d and never drained** (`browser.py:417-419`, no `communicate()` anywhere). A full 64 KB pipe buffer blocks Chrome's writes and stalls startup past the 2.25 s window. **My own `--enable-logging` (`20dbcd6c`) is an amplifier of this** — it did not cause the original failure (validation 4 failed identically without it) but it must not stay on a piped stdio path.
**G11 ✅ Passing BOTH `host` and `port` to `uc.start` switches nodriver to attach-only** (`browser.py:370-375` sets `connect_existing = True`, no browser spawned). Passing `port` alone is silently ignored for launches.
**G12 ✅ Attach mode verified end-to-end locally** (scratchpad probe, nodriver 0.48.1 + Chrome 150): we spawn Chrome with a fixed port and DEVNULL stdio, poll `/json/version` (ready in 0.70 s warm), then `uc.start(host='127.0.0.1', port=port)` → `browser.connection` present, `browser.get()` returns a Tab, `page.send(get_targets)` returns 3 targets, `page.evaluate` works, and `browser._process_pid is None` (nodriver spawned nothing — **we own the pid**).

## Technical Implementation
**Core decision: stop letting nodriver launch the browser.** We launch Chrome ourselves and attach (G11/G12). One change addresses G2, G5, G8, G9 and G10 simultaneously, and it is the only option that makes teardown reliable — every reviewer finding about process-killing dissolves when we own the pid instead of hunting for it.

* **F1 — Exact-pin nodriver** (`requirements.txt`): `nodriver>=0.48` → `nodriver==0.48.1`. Closes G3 so CI and local run identical code.
* **F2 — Launch-and-attach** (`bootstrap_session`): spawn Chrome ourselves with our stealth args **plus** the nodriver defaults we now must supply (`--remote-debugging-port=<port>`, `--remote-debugging-host=127.0.0.1`, `--remote-allow-origins=*`, `--no-first-run`, `--no-default-browser-check`, `--homepage=about:blank`, `--no-service-autorun`, `--no-pings`, `--password-store=basic`, `--disable-infobars`, `--disable-breakpad`, `--disable-dev-shm-usage`, `--disable-session-crashed-bubble`, `--disable-search-engine-choice-screen`, `--disable-features=…`), with **stdio to DEVNULL** (kills G10) and its **own process group** (`start_new_session=True` on posix). Then `wait_for_devtools()` polls `/json/version` with a generous, env-overridable budget (default 60 s — G2 gone), detects early exit and reports the return code, and falls back to reading `DevToolsActivePort` from the profile dir if the requested port never answers (kills G8/G9). Then `uc.start(host, port)` attaches.
* **F3 — Guaranteed teardown** (fixes G5 + Gemini CRITICAL): the spawned process is tracked per worker; `terminate_spawned_chrome()` kills the whole **process group** (SIGTERM, then SIGKILL after a bounded wait) and is called before every retry **and in a `finally` after the retry loop** — so a final-attempt failure cannot leak, which my draft's before-next-attempt-only placement would have. Also registered `atexit`. **No `pgrep`/`pkill` anywhere** — we kill a pid we own.
* **F4 — Version-agnostic tripwire**: `verify_proxy_extension_loaded(page)` uses `page.send(uc.cdp.target.get_targets())` and no longer reads `browser.connection` (G7). Purpose unchanged: never scrape unproxied.
* **Database Impact:** NO.

## Standards Compliance
* **Try-Catch Boundary:** teardown and `DevToolsActivePort` reads wrap per-call with WARN-and-continue; neither may become a new bootstrap-fatal path. The readiness timeout raises a *descriptive* RuntimeError (port, elapsed, process return code) — the opposite of nodriver's cause-agnostic message.
* **Unhappy Path Tests** (`npm run test:py`): readiness-poll success / timeout / early-exit-with-returncode / DevToolsActivePort fallback; launch-arg contract (debug port + host present, stealth flags preserved, single `--disable-features`); tripwire passes on a fake Tab with no `.connection` attribute at all and raises when no extension target exists; teardown is idempotent and safe when the process is already dead.
