## Context

### Goal
Land the concrete, file-by-file implementation of program-plan Phase 2 (steps 2.1–2.5): swap the mobile auth SDK from `@react-native-firebase/auth` to `supabase-js`, replace the web-based Google OAuth flow with native `signInWithIdToken`, keep phone-OTP in code but gated off at all three entry points (D15), execute the native-config wave (G6 keep/remove split + EAS credential verification), execute the MaxBLD rename this phase (Spec 117 OD-B4 — store-listing gate resolved, [panel-fold: Operator ruling 2026-07-19]), ship email confirmations ON at launch with a deep-link catch mechanism (P2-D4, [panel-fold: Operator ruling 2026-07-19]), rename the `idToken` field to `accessToken` across its full 10-site blast radius (P2-D3 REVERSED, [panel-fold: Ground truth, BLOCKING]), and rewrite the mobile test surface — all before Phase 2.4's device smoke cycle. **This document reflects the 2026-07-19 5-reviewer plan-panel adjudication** — see the Panel Adjudication appendix at the end for the full fold list.

### Why this phase is not optional polish
**P2-G1 — mobile auth is currently non-functional against the live backend.** Phase 1 has already landed in code (not just planned): `src/lib/auth/get-user.ts` verifies Supabase JWTs only (`supabase.auth.getClaims()`/`getUser()`, 3-segment shape check, no Firebase code path survives), and D6's uuid conversion has already run — `mobile/src/constants/contracts.ts:33` reads *"firebase_uid_max retired 2026-07-18 (ADR-007 / migration 229): uid columns are uuid FKs to auth.users."* Meanwhile every mobile auth file (`mobile/src/lib/firebase.ts`, `authStore.ts`, `apiClient.ts`, `sign-in.tsx`, `sign-up.tsx`) still sends a Firebase ID token as the Bearer value. `get-user.ts`'s `getClaims()`/`getUser()` calls will reject a Firebase ID token outright (wrong issuer/signature) — **every authenticated mobile API call is currently broken on any backend running Phase-1 code.** This raises this phase's priority from "next in sequence" to "restores basic app function," and means the existing 7 Jest files' Firebase mocks are already testing a contract the server no longer honors.
