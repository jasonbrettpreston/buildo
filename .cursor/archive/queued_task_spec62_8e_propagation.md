## Technical Implementation
* **`enrich-permits.js` (lock 66 — no new lock; same file/dual-target):**
  * `const CENTRELINE_COLS = ['is_corner_lot', 'is_through_lot', 'primary_frontage_street_name']`; add to `allWriteCols()` (→ auto SET + IS DISTINCT FROM write-guard + emitMeta writes).
  * **DEC-A (booleans, L12):** `cand` CTE reads `par.is_corner_lot, par.is_through_lot`; `ag` CTE aggregates `COALESCE(bool_or(is_corner_lot), false) AS new_is_corner_lot`, `COALESCE(bool_or(is_through_lot), false) AS new_is_through_lot`. **No corner/through mutual-exclusivity carve-out** (F-S6: a consolidated multi-parcel lead can be both).
  * **DEC-B (frontage scalar) [R1 A2 / R2 A-1]:** `primary_frontage_street_name` is NOT a bool_or; per §11.1 it is the **smallest-`par.id` non-NULL value** for the lead. Implement as its OWN aggregate **inside the existing `ag` CTE**, using the `cand`-projected column names (`cand` aliases `par.id AS parcel_id`): `(array_agg(primary_frontage_street_name ORDER BY parcel_id) FILTER (WHERE primary_frontage_street_name IS NOT NULL))[1]` — **`parcel_id`, NOT `par.id`** (which doesn't resolve at the `ag` altitude), value column unqualified. NOT off `dom` (dom = max-area parcel ⇒ wrong tie-break), NOT the spec's standalone CTE chain. FILTER picks the smallest-id *non-NULL* (`[1]` of an empty filtered array = NULL → correct orphan semantics). D3 known limitation.
  * **DEC-C (orphan-nullify) [R1 RG-FAIL]:** add `&& !CENTRELINE_COLS.includes(col)` to the `buildNullifyOrphansSql` generic `= NULL` filter predicate (same as `RAVINE_COLS`/`HERITAGE_COLS`), THEN append hardcoded `is_corner_lot = false`, `is_through_lot = false` (NOT NULL → DEFAULT), `primary_frontage_street_name = NULL`. **Without the filter exclusion the NOT-NULL booleans get `= NULL` → orphan UPDATE crashes (PG 23502).** Lock with `expect(sql).not.toMatch(/is_(corner|through)_lot = NULL/)` (mirrors the ravine line-44 test).
  * **DEC-D (precondition — full Spec 62 §L24 3-part guard) [R1 Gemini/DeepSeek + R2 A-2/Gemini]:** `assertCentrelineColumns` → `information_schema` check for mig 174 (source) + mig 176 (target) cols (**L24a**, fail-fast). `assertCentrelineEnriched` →
    - **L24b recency:** `pipeline_runs` shows a successful `centreline:enrich_centreline` whose `completed_at` is AFTER the most recent successful `load-parcels` (guards stale-vs-reloaded-parcels — the lineage column alone can't see recency).
    - **L24c coverage:** `COUNT(*) FILTER (WHERE centreline_dataset_version_when_enriched IS NOT NULL) / NULLIF(COUNT(*) FILTER (WHERE geom IS NOT NULL), 0) >= threshold` over **all valid-geom parcels** (the schema can't cleanly express "intersecting" — denominator is all valid-geom; healthy ≈ 97% since ~3% are zero-intersection, a partial run is ≪50%, so the gap is wide). **Threshold = tunable `logic_variable` `centreline_propagation_coverage_min` (default 0.90 — below the ~3% zero-intersection floor so a healthy run never false-HALTs; operator-overridable)** [R2 DeepSeek/RG]. Guards the mass-false-negative risk where a partial §8d silently marks most permits false/false/NULL. *(This guard is stricter than the ravine/heritage precedent (`>0` only) — deliberate per §L24; followup: consider retrofitting ravine/heritage for consistency.)*
  * **DEC-D2 (link-table guard — per target) [R1/R2 DeepSeek-HIGH + Integration/RG]:** before each target's UPDATE, verify **that target's configured link table** (`CFG[target]` — `permit_parcels` for permits, `lead_parcels` for coa) exists AND carries its join column (`information_schema.columns` for `lead_id`/`permit_num` etc.) — both missing/renamed → FAIL with a clear message (not a cryptic relation/column-not-found mid-transaction). NOT a fixed two-name probe; keyed off the live CFG.
  * Audit rows (Spec 48): INFO block `${prefix}_corner_lot_count` / `${prefix}_through_lot_count` / `${prefix}_with_frontage_name_count` after the heritage block. emitMeta reads: add the 3 parcels cols.
* **Migration 176 (M-3):** `DO $mig$ … IF EXISTS(permits)/IF EXISTS(coa_applications)` guard, `SET LOCAL lock_timeout='5s'`; per table `ADD COLUMN IF NOT EXISTS is_corner_lot BOOLEAN NOT NULL DEFAULT false, is_through_lot BOOLEAN NOT NULL DEFAULT false, primary_frontage_street_name TEXT`. No CHECK constraint (booleans + free-text). No lineage col on targets (precondition reads the parcels lineage).
* **assert-global-coverage.js (Spec 49, DEC-G):** in the permits `pa` query + CoA `ca` query add `COUNT(*) FILTER (WHERE is_corner_lot)`, `... is_through_lot`, `COUNT(*) FILTER (WHERE primary_frontage_street_name IS NOT NULL)`; push 3 `infoRow`s per target (`Step 9b — enrich_permits` / `CoA Step 4b — enrich_coa_zoning`) after the heritage rows. Booleans = TRUE-subset count (no denominator, mirrors ravine/heritage NOT-NULL-DEFAULT note); frontage name = non-null count.
* **manifest.json (Spec 40/41/42, DEC-F):** NO new step — the `enrich_permits` (chain_permits) + `enrich_coa_zoning` (chain_coa) steps already run `enrich-permits.js`; they now write 3 more cols.
