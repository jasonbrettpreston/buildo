* Steps, in order (Folds I3, D2, G3, D3, I1):
  1. Checkout (dispatched ref) → echo ref + `git log -1 -- migrations/` (audit).
  2. Standard preamble: setup-node 20 → `npm ci`; env: `SUPABASE_DATABASE_URL` secret + `SUPABASE_CA_CERT_PATH: ${{ github.workspace }}/scripts/certs/supabase-ca.pem`; the chains' empty-secret/CA-file guard step copied verbatim.
  3. **Port guard:** fail if the URL contains `:6543` (transaction pooler — CONCURRENTLY-unsafe). Cheap regex on the env var, value never echoed.
  4. Pre-state `--verify` — bare `run:` + `continue-on-error: true` + step id, watchdog pattern verbatim (`pipeline-watchdog.yml:101-115`; the shape lock pins the bare-`run:` form). **Drift-aware gate (Fold G3):** parse the `Verify: N missing, M drift` line — `drift > 0` → hard abort with `::error` (apply would silently skip drifted files); `missing`-only → proceed with `::notice` listing them.
  5. `node scripts/migrate.js --dry-run` — the real would-apply listing (Fold I1; exits 0). If `dry_run == 'true'`, the run ENDS here, green.
  6. If `dry_run == 'false'`: `node scripts/migrate.js` (apply; stops at first failure; seeds noted in summary).
  7. Final `--verify` — must be green, NOT continue-on-error.
  7b. **INVALID-index gate (Fold RC-a — the panel's sharpest catch):** after apply, `SELECT indexrelid::regclass FROM pg_index WHERE NOT indisvalid` — any row fails the run with `::error` naming the index. Failure trace it closes: a killed `CREATE INDEX CONCURRENTLY` leaves an INVALID index; the file stays MISSING (no bookkeeping row); on retry `IF NOT EXISTS` silently skips the broken index, the file records as applied, and `--verify` is green **forever** while the index is permanently broken. `--verify` diffs checksums only — this gate is the only thing that would ever see it.
  8. `if: failure()` post-mortem (Fold D3): re-run `--verify` + print `schema_migrations` tail + the INVALID-index query, so the operator sees exactly which migrations committed and whether a broken index was left behind.
