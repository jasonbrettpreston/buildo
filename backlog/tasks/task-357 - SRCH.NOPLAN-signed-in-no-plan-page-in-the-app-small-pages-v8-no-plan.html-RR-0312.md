Scope now: a user with no MaxBLD plan gets the designed "Signed in, no plan" page in the app (small-pages-v8 no-plan.html, three states) instead of the one-line subscription notice on the search page. The page is drawn from the existing content-and-binding pattern, reached when the lookup refuses with 403 AND a successful entitlement read shows no active plan (a failed read keeps today's notice). It carries NO sign-up link, because the design the operator names has none (see "The sign-up question"); the way to sign up is not built anywhere yet (see Waits on). Operator, verbatim, 2026-11-19: "b. with no plan - it needs to an error page that inludes a way to sign up" (MORNING-DECISIONS.md:1216, RR-0312, whose text names "the designed small-pages-v8 no-plan page").

In plain words: today a signed-in person with no plan taps a lot and sees "Your subscription doesn't include the parcel tool right now. This isn't a missing address — reactivate to search lots again." on the search page and nothing else: no heading, no way forward, no Log out. The designed page says "Welcome back", "This account has no active plan yet.", "Your plan is managed on the web. It's the same MaxBLD account.", one button "I've set up my plan" (re-reads the plan), and quiet links Account and Log out. Whether that counts as "a way to sign up" is the operator's call (open point 1); the honest answer today is that no one can sign up for a MaxBLD plan from inside the product yet.

The sign-up question (the design does not settle it; open point 1): the operator's words ask for "a way to sign up"; RR-0312 equates that with the designed page; the designed page has no sign-up control. Its only plan text is "Your plan is managed on the web." (no address, no link, no purchase nudge, no-plan.html:292) and its one button re-reads the plan. The reason on the mock is the operator's own 2026-11-11 ruling "a" (open-questions.md:1056) and App Store 3.1.1; Spec 126 (dated note 2026-11-11, item 1 "Rule 3 amended: in-app purchase", docs/specs/02-web-admin/126_maxbld_surface_standard.md:1113) separately allows an in-app purchase later (MF-70). Spec 126:1081 draws the same connection: "Sign in -> "Subscribe at maxbld.ca" message (no plan yet, app; no purchase in the app)" (that message is itself not in the v8 page, which names no address). This task builds the page as drawn and adds nothing the design lacks.
