## Description

<!-- SECTION:DESCRIPTION:BEGIN -->
In plain words: when the customer report reader (1.3 W) is built, it will stay switched off until launch by the one "web live" switch, which is off. After 1.3 W lands, a tester on the phone types an address, picks it and sees the page "No report for this lot yet." for every lot, the 25 test lots included, because the separate tester view (the Preview banner, MB-94 part f) is not built. Answer A: keep it so, and nobody sees a real number before launch. Answer B: bring the tester view forward into Increment 1·B, so a phone tester sees real numbers for the 25 test lots and the 1,921-lot cohort (with the Preview banner, no charge) before launch.

Grounded: yes. The switch is the constant MAXBLD_WEB_LIVE, false (src/lib/surfaces/maxbld-web.ts:19). Today only the web search page (src/app/(maxbld)/parcel-tool/SearchPageClient.tsx:17) and the web report page (src/app/(maxbld)/parcel-tool/[parcelId]/page.tsx:18) read it; the lookup route and the app do not (git grep "surfaces/maxbld-web" over src, mobile, scripts: no route or mobile file). So the plan's line "W returns nothing for the app as well as the web" is not true of today's code: the app gets nothing today only because the reader is an empty slot (src/lib/parcels/report-page.ts:23-26). It becomes true when W makes the switch its first statement (BL-W PLAN.md 1.1), which reuses a web switch for the app. With a null page the phone shows the miss page "No report for this lot yet." (scripts/surfaces/_schema/seed-report-v2.mjs:619; mobile/src/components/surfaces/ReportBinding.tsx:399-404) and the meter counts nothing (src/app/api/parcels/lookup/route.ts:45).
