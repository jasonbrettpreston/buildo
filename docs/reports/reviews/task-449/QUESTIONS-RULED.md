## Seat rulings (round 1, seats integration, reality-check, regression; board head 0841db559)
- **S-a (rc#1): the period strip breaks the stored key ". GASPAR CRT". Ruled: raw key first, stripped key on a miss.** Measured: the stack holds one parcel key with a period (21 lots) and three address-point keys; parseLinearName("St. Gaspar Crt") returns ". GASPAR CRT" (run in memory), which is the stored key, so "21 St. Gaspar Crt" is an exact hit today (RR-0442 :2276, an exact match opens), and the strip alone turns it into a list (consumer, fuzzy distance 2) or a miss (admin). "St. Clair Ave W" is the opposite case: typed period, stored none (stored key CLAIR AVE, seat case 22). The two options weighed:
  - *Stripped first, raw on a miss.* It must sit before the mistyped-street read, because that read returns a list for both streets and would end the search before any retry. That means re-running steps 1 and 2 on a second key inside resolveAddress: either wrapping about 60 lines in a function (a large re-indented diff) or duplicating them. It can also change a hit that works today: the stripped key GASPAR CRT is tried first and could match a different real street, where today's raw key hits the right one. Rejected.
  - *Raw first, stripped on a miss.* resolveAddress, when q holds a period and the raw street key differs from the stripped key, calls itself once with keepPeriods true and matchMistyped false (steps 1 to 3 on the raw key, which is exactly today's behaviour) and returns that unless it is no_match; then it runs the stripped key through every step. About 5 new lines plus the optional keepPeriods arguments (an argument, not an option, RR-0392). Every hit that works today is the same hit, because the raw run is today's run; the strip only adds hits. Cost: up to 3 reads, only for a query that holds a period and whose keys differ ("Apt. 4" parses to the same key and skips it). Ruled.
  This replaces the earlier rulings that rejected a retry (plan-error-paths#4, plan-plan-review-deepseek#2): they were made before the stack was read.
