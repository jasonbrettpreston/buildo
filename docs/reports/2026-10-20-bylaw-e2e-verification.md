# By-law answers — golden-lot end-to-end verification (2026-10-20)

Lane e2e-verify-1 (independent verifier; did not write the fixes). Branch `wf1/bylaw-e2e-1`, base **208e8a82**. DB read-only (`BEGIN READ ONLY` pulls, rolled back, under the dblock).

**Question.** Does each recorded envelope-review answer take effect on real lots? Every `wrong` correction should change the calculated result as the operator said. Every `disclose` answer's disclosure should appear for an affected lot.

**Inputs.** `docs/reference/envelope-answers.json` and `docs/reference/envelope-answer-dispositions.json` (788 answers), read through `docs/reports/generated/envelope-answer-tracker.json`. Of these, **317** answers are `wrong` (131) or `disclose` (186); all are covered. `matches`, `no_application`, `unsure` and null verdicts carry no effect to prove and are out of scope here.

**Artifacts.**
- `src/tests/fixtures/bylaw-golden-lots/lots.json`: 170 real parcels (input vectors plus their stored Spec 65 / Spec 78 columns), with no DB dependency. 111 of them are used by a check.
- `src/tests/fixtures/bylaw-golden-lots/cases.json`: 1125 cases, one per answer × zone, each with its checks and their initial-run evidence. Generated by `scripts/analysis/bylaw-validation/golden-lots-cases.mjs --write`, which `--check`s as fresh.
- `src/tests/helpers/bylaw-golden-lots.ts`: the production unit assembly, as `eval-lots.mjs` and `validate.mjs` G-EVAL build it: agreed units with adjudications applied, generated fields, displacement links, `makeContext`, and the vocab `default_overrides` design choices. It re-implements no by-law rule.
- `src/tests/bylaw-golden-lots.logic.test.ts`: PROVEN cases use `it`; FAILS use `it.fails` with the finding id and turn green when fixed; OWED cases use `it` (the unit reaches an affected real lot) plus `it.todo` (the lot-level field); NOT-EXERCISABLE cases use `it` (the reason holds).

**Calculation paths checked.**
1. The evaluator (`scripts/analysis/bylaw/evaluate.mjs` `effective()`), the only path today that reads the keyed by-law units. Every PROVEN or FAILS verdict is about this path.
2. The Spec 65 `enrich_parcels` max-build compute and the Spec 78 §1–§6 opt-config engine (`scripts/lib/max-build.js`, `scripts/lib/optimal-config.js`). Neither reads the by-law units: they use the zoning columns and constants. Spec 78 §5.2 S9 says so: *"the §P2.1 suite constants are stale … until then the table records the as-built code, not the law"*. No answer can take effect there. Their replacement is ① (see "Other findings" 2).
3. The report surface (`docs/reference/maxbld-report-field-inventory.md`) and `compute_maxbld_scenarios` (①) are not built. An answer whose effect lands only there is **OWED-TO-①**, and the case cites its field in `docs/reference/maxbld-field-lineage.json`.

## Classes

| class | meaning |
|---|---|
| PROVEN | on every listed real lot, the evaluator returns what the operator said (value, status, winner, not-applied, or the evaluator's own disclosure) |
| FAILS | it does not; the finding id and the observed result are below |

| NOT-EXERCISABLE | the operator pinned the answer out of scope, or no real lot can raise it |

### E2E-F-01 — Garden suite on a corner lot: (6)(C) cannot evaluate

- **Answers contradicted:** `150.7.60.20(6)#(6)(C)` (wrong, tracker INCORPORATED), zones R, RD.
- **Operator answer:** "The 1.5 m minimum applies to a garden suite on a corner lot only, not as the default for every garden suite."
- **Ruling:** M-179(2) (69a l.288: "(C) is the corner-lot arm outside (A)/(B), keyed `condition [corner_lot]`").
