## Verdict

The direction is right and the defensive instincts are real — loose client schema, server-side blank→null normalisation, read-only transaction, guard on the target stack, and a data-check script that even counts primary vs. any footprint — but the change ships three defects the lens was pointed at. The map's built tier is read from a second array by shared index while the card reads the same datum off the lot object, so a silent `false` is one refactor away and a wrong-lot fill is one filter away; the card asserts **"has the house"** from an any-building `EXISTS`, a distinction the author's own check script measures and then discards; and the rehearsal-only guard validates a WHATWG URL while `pg` connects from a raw connection string it parses differently, which makes the one security control in the patch bypassable. Around those sit the usual second-order damage: a `CONSUMER_MAP_COLS` that now contains a non-column, required consumer-schema fields that will break fixtures, contract paths declared but never consumed, an un-normalised blank street that can render "faces ", and a Postgres/JS trim mismatch that makes the verification tool lie in the optimistic direction. Fix the three headline items and the descriptor/check-script consistency, and this is a sound increment; ship it as-is and the surface will confidently tell a user the wrong lot is the one with the house.
