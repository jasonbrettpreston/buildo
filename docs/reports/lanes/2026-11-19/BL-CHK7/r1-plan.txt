## Verdict

This brief is well-organised and genuinely useful — the grounding-facts paragraph is the best part of it, because it states the inconvenient truths (local-only ledger, duplicate 315, the wiring gap at `gate.mjs:589`) that most briefs bury. But as a *review input* it is unsound in four ways that compound: it allocates its document budget to a 13-line stub and supplies no source for the three files the plan actually edits, so every claim about the codebase is unverifiable inside the artifact; it carries two unreconciled ruling contradictions (RR-0195/RR-0196) and two AC/step contradictions (AC1 "committed alone" vs "with the work"; AC7 "with the work" vs "last docs commit") that will be resolved ad hoc by whoever builds it; it presents truncated, quote-closed operator text and 12-hex "sha256" digests as provenance in a system whose stated guarantee is verbatim, hash-locked evidence; and the design it pre-registers is **fail-open and pre-commit-only** — the ledger branch is unimplemented, the count-based id diff cannot name what it catches, and nothing runs in CI. The single most valuable thing to fix before plan-lock is not any one line but the shape: decide whether this task is "add a check to the existing CI gate" (in which case the count heuristic, the ledger gap, and the scope split all need a ruling) or "add a fast pre-commit filter" (in which case the CI half still has to exist, because a check that a developer can skip with `--no-verify` is a suggestion, not a gate).
