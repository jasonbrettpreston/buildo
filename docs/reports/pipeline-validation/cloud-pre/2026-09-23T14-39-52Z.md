## Why each check exists

- **stranded_running_rows** — A stranded `running` row makes every dispatch SKIP before reconcile-runs.js can reap it (runbook §3b) — the dispatch is spent and nothing runs. Clear it by hand per §3b, never by re-dispatching.
- **migrations_missing** — A migration absent from schema_migrations was never applied to THIS database — the schema the descriptors were validated against is not the schema the dispatch would run against. Keyed by filename: schema_migrations has no version column and the sequence has gaps.
- **declared_guards_present** — guards.requires[] is THE preconditions, checked before the first read. A missing index is not a slower run, it is an unbounded one; a missing extension can silently switch the step to a second algorithm. on_missing:"fail" means the runner refuses outright — a dispatch would abort mid-chain.
- **table_floors** — A source table below its floor means the upstream load did not finish (or was never run) on THIS database — every downstream step would compute against a truncated population and still report a clean verdict. Tables with no declared floor are reported with their count only.
- **seed_rows_present** — LM-D15 — scripts/lib/step/config.js throws on an unseeded variable. On cloud that throw lands MID-RUN, after the dispatch is spent: this check is the same failure mode measured before dispatch instead of after.
- **sharing_chain_running** — A chain already running means the dispatch is refused/skipped rather than queued (Spec 113 §8.3 12h TTL) — a spent dispatch with nothing to show for it. Wait for the terminal status of the chain instead of re-dispatching.
