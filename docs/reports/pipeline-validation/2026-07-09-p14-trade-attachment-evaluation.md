## Synthesis + draft recommendation for P14-D (the panel decides)

### What the evidence says (at the confidence the thin corpus supports)

1. **The scope-mapped UNION design (scenario 3), as literally specified, does NOT beat the baseline.**
   On the whole corpus it is DOMINATED by pre-P13-3: lower recall (54.9% vs 62.6%), lower
   precision (31.2% vs 37.8%), and MORE inflation (18.7 vs 16.6 trades/permit). The reason is
   structural, not incidental: `mapToLines` selects archetype *lines*, and each line's "complement"
   IS the existing coarse `ARCHETYPE_BUNDLES` set (INT=13, ADD=26, FB=32). Unioning full complements
   just re-derives the same maximal bundles by a different route. **The lever the presumptive design
   was reaching for is bundle LEANNESS, not bundle SELECTION** — scope-mapping only pays off if each
   line carries a *tighter, inspection-calibrated* trade complement than today's bundles.

2. **P13-3 (evidence-only) bought precision by paying recall AND by zeroing 13 whole trades.**
   Precision(insp) rose 37.8%→65.8% and inflation fell 16.6→6.0 — real wins. But recall fell
   24.4 pts, and **13 trades now have 0 active leads corpus-wide** (caulking, decking-fences,
   eavestrough-siding, millwork-cabinetry, overhead-doors, pool-installation, security,
   site-maintenance, site-preparation, solar, stone-countertops, tiling, trim-work — every trade
   the live JS `TAG_TRADE_MATRIX` never emits directly). For a marketplace, a tiling/cabinetry/trim
   contractor now receives ZERO leads. This is the starvation the "overhead-doors check" was named
   for, an order of magnitude larger than a single trade.

3. **The demoted bundle tier was worth ~24 recall points** — but at a precision and inflation cost
   that P13-3 correctly judged unacceptable in its all-or-nothing form. The question is not "bundle
   or no bundle" but "can the recall be recovered WITHOUT the inflation" — i.e. a leaner, per-scope
   complement.

4. **The permit-type ceiling (scenario 5) is already substantially implemented** by
   `NARROW_SCOPE_CODES` early-return: PLB-coded permits are identical pre/post-P13-3 (they never
   received bundles) and the explicit ceiling changes them by 0 pts. Its only residual value is
   plumbing/mechanical *permit_types* whose `permit_num` lacks the narrow code (a small tail). It is
   a cheap, safe correctness guard but not a recall or precision mover on its own.

5. **Finer archetypes give diminishing coverage fast** — 4 existing archetypes (INT/FB/ADD/BAS)
   already cover 93% of the (residential-biased) corpus; 6 cover 96%. The gap is NOT archetype
   coverage — it is precision *within* an archetype (the coarse complement over-attaches). Adding
   more archetype *codes* would not have helped these permits; refining the *complement* of the
   existing ones would.

### Confidence limits (binding)
- Corpus = **122 permits**, deep_scrapes PAUSED. `large new-build` = n=1 (anecdotal); `mid
  multi-scope` and `PLB` = n=15/29 (low). Only `small residential` (n=77) is moderate-confidence.
- Ground truth under-covers finishing trades + electrical (no dedicated inspection stage), so
  **recall is trustworthy; absolute precision is a lower bound** — the `prec(insp)` column is the
  fair proxy and the one the comparison should lean on.
- Every number moves once deep_scrapes resumes and enlarges the corpus (a scheduling decision for
  the user, not this WF).

### Draft recommendation (data-grounded; the panel/D finalizes)
A **hybrid**, staged by evidence:
- **Keep P13-3 evidence-only as the ACTIVE tier** (it owns the precision win) — but
- **Restore recall via a LEAN, scope-mapped complement, NOT the full bundle** — i.e. adopt the
  scenario-3 *architecture* (trades flow from the same `mapToLines` scope the cost model already
  detects) but replace each line's complement with an inspection-calibrated core set (the trades
  that actually show up for that scope), attached at an explicit `inference` tier/confidence BELOW
  direct evidence — so downstream consumers can rank evidence over inference and the forecast/score
  inflation stays bounded.
- **Fix the 13-trade starvation deliberately**: for bundle-only trades that are genuinely implied by
  a scope (tiling/trim/cabinetry/countertops in a KIT/BTH/INT; overhead-doors in a GAR), the lean
  complement re-attaches them at the inference tier so they are servable again — rather than the
  current silent zero.
- **Adopt the permit-type ceiling as a cheap correctness guard** (scenario 5) layered on top — it
  costs nothing and closes the plumbing/mechanical-permit-type residual the narrow-code misses.
- **Do NOT add finer archetype codes** on this evidence — the coverage curve says the existing set
  already spans 96%; invest in leaner complements, not more archetypes.

Net: the presumptive union design is right about WHERE trades should come from (the cost mapper's
scope detection) and wrong about WHAT each scope should attach (full bundle vs lean calibrated set).
The finalized Spec 80 §5.C table (P14-D) should encode the lean per-line complements + the
evidence/inference tier contract + the permit-type ceiling, and re-measure against an enlarged
corpus once deep_scrapes resumes.
