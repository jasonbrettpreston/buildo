### #1 — `get-lead-feed.ts` feed-correctness triple (3× HIGH + 1× MED)

**Source:** WF3 (2026-05-08) DeepSeek review of `src/features/leads/lib/get-lead-feed.ts`
**File:** `src/features/leads/lib/get-lead-feed.ts` — last modified in commits `1e6e5d9` + `58a0b8f` (two of the five most recent commits)

Three bugs in the same file:
- `clampedLimit = Math.min(Math.max(1, input.limit), MAX_FEED_LIMIT)` — `input.limit` can be `undefined`; `Math.max(1, undefined) → NaN`; `LIMIT NaN::int` errors at PG. (line 986)
- `clampedKm = Math.min(input.radius_km, MAX_RADIUS_KM)` — `input.radius_km` undefined → NaN; `ST_DWithin(..., NaN)` silently returns false → empty feed. (line 985)
- `builder_candidates` CTE: `LEFT JOIN wsib_per_entity w ... WHERE w.business_size IS NOT NULL` acts as INNER JOIN — drops 30–50% of builder leads (new contractors, GTA-condition failures). (line 478)

**Why #1:** File is hot (CoA UNION arm added in the two most recent commits). NaN bugs can break the live feed for any caller that omits `limit` or `radius_km`. The builder INNER JOIN silently degrades lead volume for builders. Fixing clampedLimit/clampedKm unblocks the cursor pagination NULL CASE fix (MED, same file).

**Fix sketch:** `input.limit ?? DEFAULT_FEED_LIMIT` and `input.radius_km ?? DEFAULT_RADIUS_KM` before the clamps; remove `WHERE w.business_size IS NOT NULL` from `wsib_per_entity` join.
