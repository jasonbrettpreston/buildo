## Rules of the register

1. Protocol: Spec 124 section 4 inherited (the Spec 128 §4 mirror). A different party adjudicates.
2. A rule without a lock is not yet a rule (Spec 124 section 4.4). ONE lock per row; the Lock is in the LAST cell with the status (arm C reads it).
3. Status words: `RULED <date>` · `OWED` · `PROPOSED` · `RETIRED`. A ruled row whose lock is not built reads `OWED` with the lock path. Never an OWED marker with no lock path (`statusOf` reads it OWED forever: `cite-parse.mjs:57-70`).
4. `Six` cell: letters D P F S H E (the six principles of Spec 126 §0a), `pass`/`n/a`/`FAIL` (Spec 128 §4.9). Applies to FE rows only.
5. Locks: a RULED row's lock paths must exist; an OWED row's lock path must be a valid `src/tests/surfaces/*.test.ts` that does NOT yet exist; a `.db.test.ts` lock must be named in a CI step (test.yml). Lock: `register-locks-resolve.infra.test.ts` (FE-09).
